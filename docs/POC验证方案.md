# POC 验证方案 · 校招咨询 Agent

> 目的：用**真实数据、真实流程**验证「候选人智能问答 + 进度查询 + HR 流程后台」的可行性，而非依赖演示数据。
> 当前系统状态：候选人表已清空，仅保留 15 条基于公司真实校招流程的基线 FAQ；一切数据从 HR 后台导入开始。

## 一、POC 前置准备（你方提供）

| # | 事项 | 说明 | 状态 |
|---|---|---|---|
| 1 | **真实候选人名单** | 姓名/手机号/院校/专业/岗位/站点/当前环节，HR 后台粘贴批量导入 | ☐ |
| 2 | **真实 FAQ 30~50 条** | 以基线 15 条为骨架，补充各站点差异（面试形式、资料要求、时间点）；后台可增删改 | ☐ |
| 3 | **LLM API Key** | DashScope（通义）或任意 OpenAI 兼容端点；用于 Agent 模式（检索式回答是兜底，不依赖 Key 也能跑） | ☐ |
| 4 | 短信网关（可选） | POC 阶段验证码回显即可；上生产再接 | ☐ |

## 二、验证场景与通过标准

### A. 候选人端（核心价值验证）
| 场景 | 操作 | 通过标准 |
|---|---|---|
| A1 真实登录 | 真实手机号登录 | 导入名单内的手机号可登录，名单外被拒 |
| A2 流程问答 | 问「初面是什么形式」「体检资料要求」等 | 命中知识库给出准确回答，附依据条目 |
| A3 进度查询 | 问「我到哪一步了」 | 回答与 HR 后台该候选人状态一致（真实联动） |
| A4 超范围兜底 | 问换站点/换岗位等办不了的事 | 自动生成反馈工单，不瞎编 |
| A5 手机端体验 | 手机浏览器打开 / 添加到主屏幕 | PWA 安装后全屏运行，交互正常 |

### B. HR 后台（运营闭环验证）
| 场景 | 操作 | 通过标准 |
|---|---|---|
| B1 名单导入 | 批量粘贴真实名单 | 导入成功，候选人端立即可查 |
| B2 状态更新 | 修改某候选人环节 | 该候选人端「我的进度」实时同步 |
| B3 工单闭环 | 回复 A4 工单并勾选沉淀 | 候选人收到回复；同类新问法自动命中 |
| B4 数据看板 | 观察统计 | 环节分布/待处理工单/高频未答问题准确 |

### C. Agent 能力验证（需 LLM Key）
| 场景 | 操作 | 通过标准 |
|---|---|---|
| C1 Agent 回答 | AGENT_MODE=on 提问 | LLM 生成回答 + 引用知识条目 + 核验徽标 |
| C2 工具调用 | 问个人进度 | Agent 调用 get_my_progress 工具查库作答 |
| C3 幻觉防护 | 问知识库没有的内容 | 回答不编造，转工单或明确说明不知道 |
| C4 灰度对比 | shadow 模式跑真实流量 | agent_runs 表可对比 fixed vs agent 答案质量 |

## 三、成功标准（POC 判定）

1. **机器人解决率 ≥ 70%**：真实候选人提问中，无需人工介入即被准确回答的比例（看板统计）
2. **进度类问题 100% 不出错**：回答状态与 HR 后台记录完全一致
3. **零幻觉事故**：无编造流程/政策/结果的回答（Verifier + 兜底转工单保证）
4. **HR 效率提升可感知**：重复咨询减少、工单沉淀为 FAQ 后命中率上升

## 四、已知的边界（POC 阶段不做）

- 格慧招 / 网签系统对接：不替代，只做跟踪提醒（需对方 API 才能深入）
- 真实短信下发：验证码与通知暂为回显/记录，接网关后切换
- 简历筛选 / 测评发起：属于领队线下流程，系统只承载结果状态
- 会话存储为进程内存：服务重启后需重新登录（数据不丢，SQLite 持久化）
