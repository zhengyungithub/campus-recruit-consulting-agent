# 校招咨询 Agent · 功能规划 V0.2（候选人端 + HR 后台）

> 更新日期：2026-10-24
> 前置文档：《开发文档-校招咨询机器人 V0.1》（业务流程状态机、技术架构见该文档）
> 产品定位：**双端平台** —— 候选人端回答校招流程/进度咨询，HR 端提供流程配置与运营后台

---

## 1. 用户画像与核心场景

### 候选人（C 端）
| 场景 | 典型问题 | 痛点 |
|------|---------|------|
| 流程不解 | "校招一共有几轮？""初面之后是什么？" | 每个站点宣讲重复讲，仍有大量重复咨询 |
| 进度焦虑 | "我简历交了一周了，有结果吗？""我到哪一步了？" | 反复问 HR/领队，占用大量人力 |
| 操作指引 | "面试资料传哪里？""体检报告什么格式？""网签怎么操作？" | 指引散落在各条短信/群里，找不到 |
| 时间地点 | "我面试是几点？腾讯会议号多少？""复试在哪个酒店？" | 临时变更通知不到人 |
| 结果与后续 | "offer 什么时候发？""三方什么时候寄回来？" | HR 不方便逐个回复 |

### HR / 领队（B 端）
| 场景 | 需求 |
|------|------|
| 被重复咨询淹没 | 让机器人承接 70%+ 的重复问题，疑难的转人工 |
| 流程各站点不一样 | 流程节点、SLA、话术需要**可配置**，不是写死的 |
| 候选人状态跟踪 | 与 V0.1 的状态机看板打通 |
| 答案质量可控 | 机器人不能乱答录用/政策类问题，需要审核机制 |
| 沉淀 | 高频问题回流知识库，越用越准 |

## 2. 候选人端功能规划

### F1 身份与准入
- **绑定方式**：手机号 + 短信验证码登录（候选人手机号来自 HR 导入的初筛/测评名单，白名单外无法注册）。
- 免登通道：通知短信内带一次性链接，点开即查（适合"查个进度就走"的低频用户）。
- 一个手机号可关联多个站点/投递记录。

### F2 智能问答（核心）
分三类意图，处理策略不同：

| 意图类型 | 示例 | 处理方式 |
|----------|------|---------|
| **通用流程咨询** | 流程环节说明、材料清单、政策解释（offer/三方/体检/网签规则） | RAG 检索 HR 维护的知识库回答，附来源文档名 |
| **个人进度查询** | "我到哪一步了""我的面试资料过了吗" | 身份校验后，调用状态机查接口，基于**事实状态**生成回答；只报客观状态，不预测结果 |
| **超出能力** | "能不能帮我改面试时间""我能不能换个岗位" | 明确告知无法办理 → 生成工单转人工，告知响应时限 |

**回答红线（写进系统提示词）**：
- 不预测、不承诺录用结果；涉及"通过/录用"只引用状态机中的既定状态。
- 不回答知识库中没有的政策细节（如违约金、落户），一律转人工。
- 不透露其他候选人任何信息。

### F3 进度可视化
- 个人进度时间线（对应 V0.1 学生级状态链）：已完成 ✔ / 当前进行中 ● / 未开始 ○。
- 每个节点显示：时间、结果（如适用）、**下一步要做什么 + 截止时间**。
- 这是最能减少重复咨询的功能：很多"到哪了"其实是"下一步我该干嘛"。

### F4 主动通知（二期）
| 通知 | 触发 |
|------|------|
| 面试提醒 | 初面/复试前 24h + 1h（线上含腾讯会议号，线下含地址） |
| 资料上传提醒 | 状态变为"待传面试/体检资料"后，未上传每日催办 |
| 审核结果 | 通过：告知进入下一环节；驳回：附原因 + 补传入口 |
| 网签提醒 | 网签发起后未应约，每日提醒（时效敏感） |
| 改期提醒 | 非面试站点学生未按约定时间面试 → 提醒自行联系面试官 + 最迟次日 SLA |

### F5 资料上传（二期，与 HR 审核工作台联动）
- 短信/会话内进入上传页，按资料类型（面试资料/体检资料）分别提交。
- 格式校验（PDF/图片、大小）、重复上传覆盖旧版、上传状态回写状态机。

## 3. HR 后台功能规划

### H1 流程配置器（本后台的核心差异化能力）
- **节点模板库**：内置 V0.1 梳理的标准校招流程（17 节点），可增删改节点、调整顺序。
- **站点实例化**：新建站点 → 选模板 → 按站点类型自动开关差异节点（线上站点启用"收集面试官会议信息"，线下站点关闭）。
- **SLA 规则配置**：每个节点可配超时阈值、催办频率、升级对象（如"改期未补面 >1 天 → 提醒面试官；>2 天 → 升级领队"）。
- **责任人配置**：每节点指定角色（领队/基地人力/面试官），支持站点内多人。

### H2 知识库管理（问答质量的地基）
- FAQ 管理：问题/答案/适用范围（全公司/某站点/某环节），支持富文本与附件。
- SOP 文档上传：宣讲手册、材料清单、网签操作指引等，RAG 自动切片索引。
- **答案审核流**：新增/修改的重要答案（政策类）需管理员确认后生效。
- **问答日志回流**：机器人每条回答可被 HR 标记"答得好/答错了"，答错的 case 一键生成 FAQ 草稿。

### H3 候选人管理
- 名单导入：Excel 批量导入（姓名/手机号/院校/专业/投递岗位/站点），自动建候选人档案。
- 状态看板：站点 × 学生状态机视图（V0.1 已规划），支持手动修正状态（留审计日志）。
- 备注：HR 可给候选人打内部标签（如"改期待跟进"）。

### H4 转人工工作台
- 工单列表：机器人转人工的咨询，显示对话上下文 + 候选人状态。
- 分配与回复：指派给对应领队/HR，回复自动送达候选人。
- 回复内容自动沉淀为 FAQ 候选草稿。

### H5 通知管理
- 短信模板管理（变量占位：姓名/时间/会议号/链接）。
- 通知时机与 H1 的 SLA 规则联动配置。
- 发送记录审计（合规要求：谁在何时向谁发了什么）。

### H6 数据看板
- 咨询分析：高频问题 TOP N（反哺知识库与宣讲材料）、机器人解决率、转人工率。
- 流程分析：各站点各环节转化率、平均停留时长、SLA 达成率。

## 4. Agent 技术设计要点

### 4.1 对话处理管线
```
候选人消息
  → 意图识别（流程咨询 / 进度查询 / 操作请求 / 转人工 / 闲聊）
  → 路由：
      流程咨询 → RAG（知识库） → 生成回答（附来源）
      进度查询 → 身份校验 → 工具调用查状态机 → 基于事实生成回答
      转人工   → 创建工单 → 安抚话术 + 响应时限
  → 敏感词/红线检查 → 回复
  → 日志留存（问答对，供回流标注）
```

### 4.2 工具（Function Calling）清单
| 工具 | 说明 | 权限 |
|------|------|------|
| `search_knowledge_base` | 检索 FAQ/SOP | 所有人 |
| `get_my_progress` | 查个人状态机时间线 | 仅本人 |
| `get_my_interview` | 查面试时间/会议号/地点 | 仅本人 |
| `get_upload_status` | 查资料上传/审核状态 | 仅本人 |
| `create_ticket` | 转人工工单 | 所有人 |

### 4.3 知识库检索策略
- 语料分层：通用政策（全局）→ 站点级公告（当前站点优先）→ 环节级指引（结合用户当前状态注入）。
- 检索时把候选人的**当前环节**作为上下文，同一问题在不同环节给不同答案（如"上传资料"在面试/体检环节指向不同清单）。
- 置信度阈值：低于阈值宁可答"这个问题我需要转人工确认"，禁止编造。

### 4.4 合规与安全
- 候选人个人信息（手机号、简历、资料）加密存储；对话日志中手机号脱敏。
- 通知短信需确认候选人已获知将收到招聘相关短信（宣讲时告知/名单授权确认，需与业务方核实）。
- 数据留存期限：校招季结束后 N 个月归档删除（与 HR 确认）。

## 5. 分期落地（与 V0.1 Phase 对齐）

| 阶段 | 候选人端 | HR 端 | 验收标准 |
|------|---------|-------|---------|
| **MVP** | FAQ 问答 + 个人进度时间线 + 转人工；白名单登录 | 知识库维护 + 候选人名单导入 + 状态看板 | 一个站点试点：机器人承接 ≥60% 咨询，转人工 ≤2h 响应 |
| **二期** | 主动通知（面试/资料/网签提醒）+ 资料上传 | SLA 引擎 + 流程配置器 + 审核工作台 + 短信模板 | 资料催办、面试提醒全自动；HR 配置新站点 ≤10 分钟 |
| **三期** | — | 问答日志回流分析 + 数据看板 + 表格自动生成（V0.1 Phase 3） | 高频问题月度报告自动产出 |

### MVP 最小闭环建议
第一版只做三件事，快速验证价值：
1. HR 导入一个站点的候选人名单 + 上传该站点 SOP/FAQ（≈ 30 条常见问题）。
2. 候选人可问答 + 查个人进度时间线。
3. 答不了的转工单，HR 在后台回复。

这个闭环不依赖格慧招/网签/腾讯会议任何外部 API（状态由 HR 导入或手动更新），两周内可出原型。

## 6. 待确认问题（新增/更新）

1. **候选人端载体**：微信 H5？公众号/小程序？企业微信对外客户？还是纯短信+网页链接？（决定登录方式与开发成本，**H5 + 短信触达**是最低成本组合）
2. 候选人名单中手机号的使用授权方式（宣讲时口头告知是否足够，需业务方确认）。
3. HR 后台使用者规模与角色划分（领队/基地人力/领导是否需要不同权限视图）。
4. 是否有现成 SOP/FAQ 文档可作为知识库冷启动语料。
