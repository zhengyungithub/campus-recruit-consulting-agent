  - **问题**：口径稳定后剩下的失败里有一类是**稳定的**——#17/#21/#33 连续多轮判负，

  - **实现**：新增 `graph.node_force_act` + `planner.pending_required()` + 计划里 `required` 标记，
    图结构 `agent → force → agent ⇄ act`。三条边界写死在代码里：
    ① **只补只读工具**（`planner.READ_ONLY_TOOLS`；`create_ticket` 永不自动执行——

    ③ 回灌用 **HumanMessage 而非 ToolMessage**（上一条 AIMessage 无 tool_calls，
       挂 ToolMessage 会因 tool_call_id 失配被 DashScope 拒）。
  - **连带修掉内部字段泄漏**（§4.4 第 25 条）：`knowledge_search` 返回的 `source`

  - **中间态教训**：只做补执行、还没修 `source` 那轮（#48）是 92.9% 且出现 1 次降级 +
    1 次内部泄漏。**新能力会暴露旧缺陷**：把裸 JSON 回灌给模型 = 邀请它照抄内部字段。

- **S4.5 回归门禁脚本化完成（eval_runs #83~#88）**：
  - **两档门禁**（`app/gate.py`）：快检 intent+fixed **约 7 秒、无需停服务**；
    全量 +agent 约 2.5 分钟、**必须先停 uvicorn**。
    "快检不用停服务"是实测结论：**固定管线走 `_faq_search`（SQL+关键词），压根不碰 Qdrant**。
    这一点决定了门禁能不能挂 pre-commit——否则每次提交都要先停服务，钩子必然被 `--no-verify` 掉。
  - **每个模式跑独立子进程**：不只为了隔离崩溃。Qdrant 本地模式是文件锁，
    一个模式跑完进程退出、锁即释放，下一个模式的 worker 子进程才打得开库。
  - **基线** `app/evals/gate_baseline.json`（纳管）：`min_passed_rate`（下限）
    + `known_fail`（白名单，在内只提示不算回归）+ `tolerance`（agent 0.05 容忍模型抖动）
    + `total`（条数一变就要求先更新基线，不做无意义比较）+ `require_dense`。
    当前：intent/fixed 下限 1.0；agent 下限 0.926、白名单 [33]。
  - **⚠️ 最重要的一条：门禁要防的是假绿灯，不是漏跑。**
    实测 uvicorn 运行时跑全量，agent 给出 **42/42 = 100%**（真基线 95.2%）。
    原因：向量库打不开 → 静默降级纯关键词 → 命中的是字面高匹配条目 →
    更容易命中**同样按字面措辞写的 `must` 断言**。**用关键词评测关键词，当然满分。**
    所以给 `retrieval` 加了降级计数，agent 档位强制校验，打不开判
    **环境冲突（退出码 3）拒绝给结论**而非放行。
    **原则：拿不到有效信号时门禁应拒绝给结论——会撒谎的门禁比没有门禁更糟。**
  - **门禁上线当天就抓到一个真缺陷**（它藏在"通过率达标"背后，靠白名单外的新失败暴露）：
    #24 把工具裸 JSON 抄进答案「依据条目：{"question": "...", "score": 0.6868}」。
    S4.4 只删了 `source`；这次删掉 `score` 后模型**照样抄 JSON 这个壳子**——
    **删字段是打地鼠，根因是"给模型看了结构化数据"**。
    修法：拆双通道——`knowledge_search` 返回**自然语言**，
    结构化命中走 `tools.take_kb_hits()` 旁路供引用/看板用，模型看不见。
    引用事件的 `score` 一并去掉（取不到就别填，恒定输出 0 是在撒谎）。

  - **验证门禁有效**：注入回归（`_faq_search` 排序反向）→ 退出码 2，

## S5.3 · 事件触发主动推送（Agent 改造最后一项，已完成）
